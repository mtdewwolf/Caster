B-02High Zero authentication on all API routes, including filesystem browsing and destructive operations (design flag)

Account-free mode hardcodes every request to user 'public'. Consequences beyond media playback: GET /api/fs/browse lists any absolute directory on the host; DELETE /api/media/:id/file needs only a guessable header (X-Caster-Confirm-Delete = media id); /api/system/cache/clear, /api/system/transcodes/kill, scan control are all open. Startup does print a security notice and docs warn to keep the server private — but DNS-rebinding or a misconfigured port-forward exposes full filesystem enumeration and file deletion.

Impact: deployment-hazard posture rather than a code defect; blocked on a decided remote-user/auth roadmap before mobile clients ship.

Locationapps/server/src/routes/api.ts (fs/delete/system routes) · src/identity.ts
MitigationTailscale-only exposure today; consider LAN-origin pinning or an opt-in shared-secret for destructive routes
B-03Medium Global scanStatus races across concurrent per-library scans

The lock layer deliberately supports parallel scans of different libraries, but progress state lives in one module-global object (scanStatus) overwritten by every scanLibrary(): concurrent runs clobber each other’s counters/current file, and the first finisher flips isScanning=false while another scan still runs. The route-level isScanning → 409 guard also rejects legitimate concurrent per-library requests that the lock layer would allow.

Locationapps/server/src/scanner/indexer.ts:45-52
FixKey status by library id (map), or aggregate it inside the lock store

B-05Medium Accessibility: core navigation cards are click-only divs; icon-only controls lack accessible names

Primary browsing targets — MediaCard/SeriesCard posters, episode rows, watch-history titles — are clickable <div>/<h3 onClick> elements with no role, tabindex, or keyboard handler: unreachable by keyboard and invisible to screen readers, some with nested interactive play buttons. In VideoPlayer, most icon-only controls use title= only (no aria-label), popovers are plain divs without aria-expanded, and music tabs implement tablist without arrow-key roving focus. Focus-trap usage in modals is a strong point to preserve.

Locationsapps/web/src/components/MediaCard.tsx:27 · SeriesCard.tsx:25 · SeriesDetailPage.tsx:210 · ProgressPage.tsx:301 · VideoPlayer.tsx (controls) · MusicLibraryPage.tsx:150
FixConvert card containers to real buttons/links with keyboard handlers; add aria-labels
B-06Low Non-transactional progress upsert can strand title_id NULL

ProgressModel.upsert performs the INSERT…ON CONFLICT and the separate UPDATE … SET title_id=… as two statements outside a transaction. A crash between them leaves resume-point rows without logical-title linkage until the next write, silently degrading title-level “continue watching”.

Locationapps/server/src/db/index.ts:892-928
FixWrap both statements in one transaction (project already uses them elsewhere)
B-07Low Search terms not escaped for LIKE wildcards (%/_)

User search text flows into LIKE '%…%' without escaping, so typing % or _ changes match semantics (e.g., % matches everything). Harmless security-wise — parameters stay bound — but produces confusing/noisy results across media, series, and music search.

Locationsapps/server/src/db/index.ts:262 · db/music-library.ts (series search similar)

B-13Info SQLite variable-limit risk with very large library sets in scope clauses

Scope filters bind one parameter per library path into NOT IN (?,…); SQLite’s historical 999-variable ceiling could reject queries for deployments with hundreds of libraries/temp-table inputs. Unlikely in practice, cheap to future-proof by chunking or joining a temp table.
